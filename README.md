# УЧЁТ — веб-версия для Netlify

Веб-приложение для каталога, складского учёта, сертификатов и документов. Фронтенд размещается на Netlify, API работает через Netlify Functions, данные — в Netlify Database (PostgreSQL). Локальная SQLite-база из предыдущих архивов на Netlify не используется.

## Что входит в архив

- `static/` — интерфейс приложения.
- `netlify/functions/api.mjs` — API, авторизация, складские операции, импорт XLSX, загрузка PDF, экспорт XLSX/PDF.
- `netlify/database/migrations/20261112120000_initial.sql` — схема PostgreSQL и исходные данные.
- `seed-files/` — исходные документы клиента для справки.
- `netlify.toml` — публикация сайта и маршрутизация API.

В базу при первом развёртывании загружаются:
- 5 демонстрационных товарных карточек из примера счёта;
- 3 производителя;
- 7 сертификатов со статусом «На проверке»;
- 241 строка номенклатуры из списка продукции собственного производства;
- 3 оригинальных PDF сертификатов.

Сопоставление 241 строки со всеми 5 товарами автоматически не выполняется: артикулы и форматы в источниках различаются. Не назначайте сертификаты товару без сверки оригинала.

## Развёртывание на Netlify

**Важно:** архив нельзя просто перетащить в Netlify как набор HTML-файлов. Так опубликуется только интерфейс, а API и база не запустятся. Для Functions и Database нужен Git-based deploy или Netlify CLI.

1. Создайте репозиторий Git в GitHub и загрузите в него всё содержимое этого архива.
2. В Netlify выберите Add new project → Import an existing project → GitHub и подключите репозиторий.
3. В настройках сборки укажите:
   - Base directory: пусто (корень репозитория)
   - Build command: `npm run build`
   - Publish directory: `static`
4. Используйте Netlify Free / credit-based plan. По актуальной документации Netlify бесплатный план включает лимит 300 кредитов в месяц и доступ к serverless functions и Database; активная база расходует кредиты по фактическим вычислениям и трафику. На Free предусмотрено 300 кредитов в месяц и жёсткий лимит: при исчерпании проекты могут быть приостановлены до следующего цикла. Netlify Database доступна на credit-based планах и расходует кредиты за вычисления и трафик; это не безлимитный бесплатный хостинг.
5. При первом deploy Netlify обнаружит `@netlify/database`, создаст PostgreSQL-базу и применит миграцию. Если база не создалась автоматически, откройте проект → Data & Storage → Database и создайте базу вручную, затем повторите deploy.
6. Дождитесь успешного production deploy. Не используйте Deploy Preview для постоянной рабочей базы: у previews отдельные ветки базы.
7. Откройте опубликованный адрес. При первом входе появится форма создания администратора. Создайте уникальный логин и пароль не короче 12 символов.
8. В разделе «Пользователи» администратор может добавить ещё до двух сотрудников.

Требования: Node.js 22 (или минимум 20.12.2), Netlify Functions, Netlify Database. Пакеты устанавливаются автоматически из `package.json`.

## Реализованные функции веб-версии

- Авторизация: первичная настройка администратора, вход/выход, PBKDF2-хеширование паролей, HttpOnly/Secure/SameSite cookie, сессия 12 часов. Первичное создание администратора и лимит трёх пользователей защищены транзакционными блокировками.
- До 3 пользователей, роли администратора и сотрудника; управление учётными записями доступно администратору. Данные общей PostgreSQL-базы автоматически перечитываются в открытых вкладках примерно каждые 12 секунд, когда пользователь не редактирует форму (это периодическое обновление, не WebSocket).
- Каталог товаров: поиск, добавление, редактирование, архивирование, импорт XLSX по артикулу.
- Справочники клиентов, поставщиков, производителей.
- Реестр сертификатов и деклараций, статусы, сроки, ручное редактирование.
- Каталог 241 позиции из исходного DOC и ручное сопоставление с карточкой товара.
- Загрузка PDF до 5 МБ, хранение в PostgreSQL, извлечение текста и поиск номера BYPR; новые распознанные номера создаются со статусом «На проверке».
- Несколько складов, приход партиями, FIFO-списание, ручной расход, перемещение, возврат, инвентаризационная корректировка.
- Документы реализации: создание черновика, выбор склада, проведение с FIFO-списанием, отмена с обратными движениями.
- Экспорт документов в XLSX и PDF с кириллицей.
- Резервная копия данных и загруженных PDF в ZIP (таблицы выгружаются в JSON).

## Что нужно согласовать перед реальной бухгалтерской эксплуатацией

1. **Форма счёта-фактуры.** Экспорт — универсальный шаблон, а не точная копия образца заказчика. Поля, подписи, формат нумерации и оформление нужно сверить с бухгалтером.
2. **НДС.** В документе доступны три режима: цена уже включает НДС (налог выделяется из суммы), цена указана без НДС (налог начисляется сверху), либо НДС не начисляется. Это настройки расчёта, а не автоматическое определение налогового статуса продавца. Ставки, применимость режима и официальный шаблон должен подтвердить бухгалтер.
3. **Сертификаты.** Система извлекает номер BYPR из текста PDF, но не подтверждает юридическую действительность, применимость к товару или дату окончания. Эти сведения нужно проверить по оригиналу.
4. **Полный товарный каталог.** В исходных материалах есть 241 строка списка продукции собственного производства, но это не полный каталог всех закупаемых клиентом товаров. Клиент должен предоставить полный актуальный XLSX-каталог с артикулами, названиями, ТН ВЭД, производителями, единицами, ценами и НДС.
5. **Права пользователей.** В этой версии сотрудник имеет доступ к основным операциям; детальное разграничение по отдельным действиям (например, запрет проводить документы или менять сертификаты) не настроено.
6. **Восстановление.** ZIP-резервная копия выгружает таблицы и вложения, но автоматическая загрузка ZIP обратно через интерфейс пока не реализована. Проверяйте скачивание и храните копию отдельно.

## Проверка перед использованием

Сначала создайте тестового администратора и проверьте на тестовых данных:

1. добавить товар;
2. оформить приход на склад;
3. создать черновик реализации;
4. провести документ и убедиться, что остаток уменьшился;
5. отменить документ и убедиться, что остаток восстановился;
6. переместить товар между складами;
7. выполнить инвентаризацию;
8. загрузить PDF и проверить номер;
9. скачать XLSX, PDF и резервную копию.

Не загружайте реальные клиентские данные до успешной проверки этих сценариев и согласования бухгалтерского шаблона.


## Важное о синхронизации

Все пользователи одного production-сайта работают с одной production PostgreSQL-базой. Изменения сохраняются централизованно. Открытые страницы обновляют данные опросом примерно раз в 12 секунд; пока пользователь вводит данные в поле или открыт диалог редактирования, автоматическое обновление приостанавливается, чтобы не стереть ввод. Для мгновенного обновления без задержки нужен отдельный realtime-канал (WebSocket/SSE), которого в этой версии нет.

## Результат дополнительного аудита исходного архива v2 (12.11.2026)

В исходниках выполнены дополнительные исправления:
- резервная копия доступна только администратору;
- операции изменения остатков блокируют строку товара, чтобы сериализовать конкурирующие операции по одному товару, в том числе при нулевом остатке;
- при импорте XLSX ранее архивированный товар снова становится активным;
- в журнале перемещение теперь отдельно обозначает расход с исходного склада;
- защитные HTTP-заголовки применяются ко всему сайту, а не только к ссылкам PDF.

Проверено локально: `node --check` для API и фронтенда, `npm run build` (проектный скрипт синтаксической/структурной проверки), целостность ZIP и наличие трёх оригинальных PDF в SQL seed-данных. Полный `npm install` в среде аудита завершить не удалось из-за тайм-аута сети; Netlify deploy, подключение PostgreSQL и реальные интеграционные тесты не выполнялись.

### Известные блокеры до передачи заказчику

- Выбор типа «Счёт», «Счёт-фактура» или «Накладная» сейчас не меняет поведение проведения: проведение любого такого документа списывает склад. Это бизнес-правило нужно согласовать и затем изменить код.
- Нет импорта нового файла списка сертификатов DOC из интерфейса; исходный список на 241 строку уже включён в начальную миграцию.
- Для PDF, где номер не распознан, нет отдельного интерфейса последующей привязки загруженного файла к существующей записи сертификата.
- Резервная копия скачивается, но загрузка/восстановление из неё через интерфейс не реализованы.
- Для клиентов, поставщиков и производителей есть просмотр/добавление, но нет полноценного редактирования и архивирования.
- Права сотрудника пока широкие: детальные ограничения на изменение справочников, сертификатов и проведение документов не настроены.
- Автообновление между пользователями — polling примерно раз в 12 секунд, а не мгновенный realtime.
- Шаблон документов и способ расчёта НДС не подтверждены бухгалтером; это не готовая официальная форма счёта-фактуры.

**Статус:** кандидат на тестовый deploy, не production-ready. Не загружать реальные данные клиента до успешного deploy на отдельном тестовом сайте, интеграционных проверок и согласования перечисленных бизнес-правил.


## Доработка импорта и управления данными

В интерфейсе импорт прайса выполняется в браузере: XLSX разбирается локально, а на сервер отправляется только список товарных полей. Это позволяет не передавать 131-МБ исходный файл через лимит Netlify Functions. Для чтения Excel используется SheetJS из CDN; для работы импорта требуется доступ браузера к cdn.sheetjs.com.

Для прайса РБ FCA поддерживаются колонки «Код изделия», «Наименование», цена без НДС, цена с НДС и ставка НДС (если обе цены есть в файле — сохраняются обе; если одна отсутствует, вторая рассчитывается по ставке). Лист с названием, содержащим «Уходящие», импортируется как архивные позиции; остальные листы — как активные. Артикул используется для обновления существующей карточки, повторный импорт не создаёт дубликаты. Формулы Excel и картинки прайса не переносятся. ТН ВЭД и сертификаты из этого файла не извлекаются, поскольку в нём нет соответствующих столбцов.

В справочниках клиентов, поставщиков и производителей добавлены редактирование и удаление. В разделе склада доступно удаление склада. Для товаров доступны архивирование и удаление; товар с историей складских операций или документами автоматически архивируется вместо физического удаления. Сертификаты можно удалять только если на них не ссылаются партии, файлы, привязки и каталог сертификатов. Черновики и отменённые документы можно удалить; проведённый документ сначала необходимо отменить. Удаление записей, связанных с историей, блокируется с объяснением причины.

Проверки в этой сборке: синтаксис `node --check` для API и интерфейса. Это не заменяет интеграционные тесты на Netlify с реальной PostgreSQL-базой.

## Последние изменения (17.11.2026)

- В каталоге товаров доступны множественный выбор, массовое архивирование и массовое удаление. При массовом удалении позиции с партиями, движениями, документами или привязками к каталогу сертификатов автоматически отправляются в архив; остальные удаляются.
- Для товара хранятся отдельные цены продажи с НДС и без НДС. Импорт XLSX пытается распознать обе колонки; если доступна только цена без НДС, цена с НДС рассчитывается по ставке.
- В новом документе можно выбрать режим: цена включает НДС, НДС начисляется сверху или реализация без начисления НДС. Режим и расчёт отражаются в экспорте PDF/XLSX. Старые документы трактуются как «цена включает НДС».
- Добавлены миграции `20261117130000_document_vat_mode.sql` и `20261117130100_product_price_without_vat.sql`. Перед публикацией убедитесь, что обе миграции применены к облачной PostgreSQL.

**Важно:** выбор «Без НДС» является настройкой расчёта документа, а не подтверждением права продавца не начислять налог. Налоговый режим и ставку должен подтвердить бухгалтер заказчика.
